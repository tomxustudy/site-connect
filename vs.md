---
  Site Connect vs Factory 对比报告

  一、项目结构

  两个项目结构基本一致，都是 monorepo 架构：
  - admin/ - Web 管理后台
  - backend/ - Express.js 后端 API
  - miniprogram/ - 微信小程序（Taro + React）

  ---
  3. 小程序 - API 配置 (config)

  site-connect 采用新结构：
  // miniprogram/src/config/index.ts
  export const getApiBase = () => API_BASE;  // 指向 localhost:3000
  - 导入路径：import { getApiBase } from '../config'

  factory 采用旧结构：
  // miniprogram/config/dev.ts
  export const config = { baseUrl: 'http://localhost:3000' };
  - 导入路径：import { config } from '../../config'

  注意：Site 新增了 src/config 目录，并把 config/index.ts 改为 Taro 配置文件格式。

  ---
  4. 登录页 (pages/login/index.tsx)

  差异很小，仅导入方式不同：
  - site: import { getApiBase } from '../config';
  - factory: import { config } from '../../config';

  ---
  5. 后端 (backend/src/index.ts)

  核心业务逻辑基本一致，都包含：
  - 多租户支持 (tenant_id)
  - 角色权限 (super_admin, clerk, worker)
  - JWT 认证
  - 微信手机号登录 (/api/wechat/login)
  - 记录 CRUD
  - 用户/工地管理
  - Excel/照片导出

  潜在差异：Site 的后端可能有更新的安全处理（如异常捕获、日志增强），需要对比具体 git 提交。

  ---
  6. 数据库

  两个项目的 SQL 迁移文件结构相似，都包含：
  - tenants 表 - 租户
  - users 表 - 用户（含 tenant_id, role, phone）
  - sites 表 - 项目工地
  - records 表 - 现场记录

  注意：Site 新增了 backend/database/migration_0204_multitenant.sql 用于多租户迁移。

  三、建议同步项

  如果你想让 factory 同步 site 的修改，主要需要做：

  1. 统一 config 导入方式 - factory 需要从 src/config/index.ts 导入 API_BASE
  2. 首页文案调整 - 根据实际业务场景选择
  3. 记录页标签 - 根据实际业务场景选择
  4. 如有新功能 - 如 custom-tab-bar，需复制相关文件
